cmdk Go Rewrite - Lean v1 Design
=================================

Motivation
----------

The primary driver for rewriting cmdk in Go is **distribution**:

- Today, installation requires `git clone` into the home directory and manually sourcing shell scripts
- Go enables packaging via goreleaser + Homebrew tap, so installation becomes `brew install mieubrisse/tap/cmdk`
- Secondary benefit: collapsing the 4-script subprocess chain into a single binary

This is NOT a feature rewrite. The goal is **exact feature parity** with the current shell implementation, packaged for easy distribution.

User Experience
---------------

### Before (current)

```bash
# Install
brew install fzf fd bat tiv poppler
git clone https://github.com/mieubrisse/cmdk.git ~/.cmdk

# Add to .bashrc/.zshrc
source ~/.cmdk/cmdk.sh

# Or .config/fish/config.fish
source ~/.cmdk/cmdk.fish
```

### After (Go rewrite)

```bash
# Install
brew install mieubrisse/tap/cmdk

# Add to .bashrc/.zshrc/.config/fish/config.fish
eval "$(cmdk init)"
```

Runtime dependencies (fzf, fd, bat, tiv, poppler) remain the same - cmdk does not replace them.

Architecture
------------

### What the Go binary does

The Go binary replaces `cmdk-core.sh`, `list-files.sh`, and `preview.sh`. It does NOT replace the thin shell function that calls it - that function must live in the user's shell process to `cd` and invoke `$EDITOR`.

### Subprocess chain comparison

**Before:**
```
cmdk()  [shell function]
  -> bash cmdk-core.sh  [subprocess]
       -> fzf
            FZF_DEFAULT_COMMAND: bash list-files.sh  [subprocess]
            --preview: bash preview.sh {}             [subprocess]
```

**After:**
```
cmdk()  [shell function, generated by `cmdk init`]
  -> cmdk  [Go binary]
       -> fzf
            FZF_DEFAULT_COMMAND: cmdk list-files  [same binary, subcommand]
            --preview: cmdk preview {}             [same binary, subcommand]
```

### Commands

1. **`cmdk`** (default command) - Main entry point
   - Calls `fd` for file listing, pipes to `fzf`
   - Categorizes selected files by MIME type
   - Opens non-text files (PDFs, images, .key) via `open`/`xdg-open`
   - Writes text file paths to temp file
   - Outputs `<temp_path>|<dir_path>` to stdout
   - Flags: `-o` (current dir only), `-s` (subdirectories)

2. **`cmdk init`** - Shell initialization
   - Reads `$SHELL` to auto-detect shell type
   - Outputs the shell function definition to stdout
   - User adds `eval "$(cmdk init)"` to their rc file
   - Supports bash, zsh, fish

3. **`cmdk preview <path>`** (hidden) - Preview for fzf
   - Called by fzf's `--preview` option
   - Dispatches to bat, ls, tiv, or pdftotext based on file type
   - Uses `os.Executable()` to self-reference in fzf's preview command

4. **`cmdk list-files`** (hidden) - File listing for fzf
   - Called via `FZF_DEFAULT_COMMAND`
   - Invokes `fd` with appropriate excludes and mode
   - Appends special entries (HOME, .., /, /tmp/)
   - Passes through flags from parent: `-o`, `-s`

### Shell function (generated by `cmdk init`)

The generated shell function is deliberately thin. For bash/zsh:

```bash
function cmdk() {
    local result
    if ! result="$(command cmdk run "$@")"; then
        return 1
    fi

    local text_files_filepath dir_to_cd
    IFS="|" read -r text_files_filepath dir_to_cd <<< "${result}"

    if [ -n "${dir_to_cd}" ]; then
        cd "${dir_to_cd}" || return 1
    fi

    if [ -n "${text_files_filepath}" ]; then
        local text_files=()
        local editor_cmd

        # Handle zsh vs bash word splitting
        if [ -n "$ZSH_VERSION" ]; then
            editor_cmd=( ${(z)${EDITOR:-vim -O}} )
        else
            IFS=' ' read -r -a editor_cmd <<< "${EDITOR:-"vim -O"}"
        fi

        while IFS= read -r line || [ -n "${line}" ]; do
            text_files+=("${line}")
        done < "${text_files_filepath}"

        rm -f "${text_files_filepath}"

        if [ "${#text_files[@]}" -gt 0 ]; then
            "${editor_cmd[@]}" "${text_files[@]}"
        fi
    fi
}
```

Note: the shell function deletes the temp file after reading it. This is the simplest cleanup strategy.

### Package responsibilities

**`cmd/`** - Cobra commands. Thin wrappers that parse flags and call internal packages.

**`internal/listing/`** - Builds and executes `fd` commands. Manages exclude lists. Adds special entries (HOME, .., /, /tmp/). Handles the three modes (system, pwd, subdirs). This replaces `list-files.sh`.

**`internal/categorize/`** - Takes selected file paths, determines category (directory, text, open-target) using `file -b --mime-type`. Simple switch statement. This replaces the categorization in `cmdk-core.sh`.

**`internal/preview/`** - Dispatches preview to the right tool. Text -> bat (fallback: cat). Directory -> ls. Image -> tiv. PDF -> pdftotext. ZIP -> unzip -l. This replaces `preview.sh`.

**`internal/platform/`** - Platform-specific behavior. Currently just the `open` command (macOS: `open`, Linux: `xdg-open`).

**`shell/`** - Go-embedded shell templates for `cmdk init`. Uses `text/template` to inject the binary path.

Key Design Decisions
--------------------

### Keep fd as external dependency

`fd` handles file traversal, ANSI coloring, `.gitignore` respect, and speed optimization. Reimplementing this in Go would be a massive effort with no user benefit. The Go binary calls `fd` as a subprocess.

### Keep fzf as external dependency

`fzf` is the entire UI. There is no value in reimplementing it.

### MIME detection via `file` command

The current shell version uses `file -b --mime-type`. The Go version does the same. No need for a Go MIME library — `file` works, is already installed on macOS/Linux, and matches existing behavior exactly.

### No config file

Configuration is via flags (`-o`, `-s`) and environment variables (`$EDITOR`, `$SHELL`). No config file for v1.

### Shell function handles editor + cd

The Go binary cannot `cd` the parent shell or reliably parse `$EDITOR` (which may contain flags like `vim -O`). The shell function handles both, exactly as today.

### Temp file cleanup in shell function

The shell function deletes the temp file after reading it. No cleanup registry needed. No stale file cleanup needed. If the shell function crashes (extremely rare for ~20 lines of shell), the temp file is in `/tmp` and the OS cleans it up.

What's Explicitly NOT in v1
---------------------------

These are all deferred to v1.1+:

- Health check command (`cmdk health`)
- Cleanup command (`cmdk cleanup`)
- `--no-open` flag
- `--log-level` flag / structured logging
- MIME type caching
- ExternalCommand interface / mock infrastructure
- Config struct / config validation
- Golden file tests
- CI matrix (multi-OS, multi-Go-version)
- Migration script from shell version
- Windows support

Risks
-----

### fzf preview self-reference

The Go binary needs to tell fzf to call `cmdk preview {}`. It uses `os.Executable()` to find its own path, resolves symlinks (important for Homebrew), and quotes the path for shell safety.

### ANSI color passthrough

`fd --color=always` outputs ANSI codes. These must pass through to fzf unchanged. The Go binary must not strip or parse these codes. `fzf --ansi` handles rendering.

### Path quoting for fzf

When fzf substitutes `{}` in the preview command, it handles quoting. The Go binary receives the path as a clean argument from Cobra — no manual unquoting needed.

Success Criteria
----------------

- `brew install mieubrisse/tap/cmdk` works
- `eval "$(cmdk init)"` in .bashrc/.zshrc works
- `source (cmdk init | psub)` in config.fish works (or fish equivalent)
- All current functionality preserved: system/pwd/subdirs modes, file preview, file categorization, editor opening, directory cd, open-target launching
- No new runtime dependencies beyond what the shell version requires
- Works on macOS and Linux
